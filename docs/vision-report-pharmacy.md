# 图片报告解读与拍照问药设计方案

## 目标

在现有大健康助手中增加两个轻量能力：

- **看报告**：用户拍摄或上传检查/检验报告图片，系统识别医学指标并进入报告解读模式。
- **拍照问药**：用户拍摄药盒或追溯码，系统识别药品信息并进入药管家模式。

本方案不引入 OCR 流水线。图片识别统一交给配置的 OpenAI-compatible 多模态模型完成，默认使用 ARK，后续解释继续复用现有 `report_agent`、`pharmacy_agent`、技能系统和 SSE 卡片流。

## 设计原则

1. **识别和解读分离**：多模态模型只负责“看图提取信息”，医学解释仍由现有 Agent 完成。
2. **最小改动**：不新建复杂业务系统，不引入报告数据库；第一版只打通图片输入到聊天解读。
3. **隐私优先**：报告图片默认模糊展示，模型输出不得包含姓名、身份证号、手机号、就诊卡号等个人信息。
4. **不编造**：看不清或无法确认的字段必须标记为“无法确认”，不得补全猜测。

## 用户流程

### 看报告

```text
用户点击“拍照上传新报告”
  -> 前端拍照/选择图片
  -> 聊天中展示模糊报告预览
  -> 上传到 /api/vision-chat
  -> 后端调用配置的多模态模型识别报告
  -> 识别结果转成一条 report 模式用户消息
  -> report_agent 调用 lab_interpreter 并生成解读
  -> 前端渲染流式文本和 report_analysis 卡片
```

### 拍照问药

```text
用户点击“拍药盒”或“扫追溯码”
  -> 前端拍照/选择图片
  -> 上传到 /api/vision-chat
  -> 后端调用配置的多模态模型识别药品信息
  -> 识别结果转成一条 pharmacy 模式用户消息
  -> pharmacy_agent 调用 search_drug_info / medication_calculator 等工具
  -> 前端渲染用药说明、禁忌、注意事项和相关卡片
```

## 后端接口

新增一个统一接口：

```http
POST /api/vision-chat
Content-Type: multipart/form-data
```

请求字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `file` | image | 用户上传的报告、药盒或追溯码图片 |
| `scan_type` | string | `report`、`drug_box`、`trace_code` |
| `user_info` | JSON string | 年龄、既往病史、长辈模式等现有用户信息 |
| `messages` | JSON string | 可选，当前聊天上下文 |

响应保持和 `/api/chat` 一致，使用 SSE：

```text
data: {"type":"node_start", ...}
data: {"type":"text", "content":"..."}
data: {"type":"card", "payload": {...}}
data: {"type":"finish"}
```

第一版可以不返回单独的识别确认结果，而是直接将识别结果注入对应 Agent。后续如果需要人工修正，再增加“识别确认卡”。

## 多模态模型适配

建议新增：

```text
backend/agents/vision.py
```

职责：

- 校验图片类型和大小。
- 根据 `VISION_PROVIDER` / `VISION_MODEL` 调用支持图片输入的兼容模型。
- 根据 `scan_type` 选择提示词。
- 返回脱敏后的纯文本识别结果。
- 不保存图片，不打印图片内容和模型原始全文。

推荐限制：

- 支持 `image/jpeg`、`image/png`、`image/webp`。
- 单张图片最大 8 MB。
- 请求超时后返回结构化错误，不进入 Agent 解读。

## Prompt 设计

### 报告图片

```text
请识别这张检查/检验报告图片中的医学信息。
只提取报告类型、检查项目、数值、单位、参考范围、异常标记、报告日期。
不要提取或输出姓名、身份证号、手机号、住址、就诊卡号、病历号、条形码号等个人身份信息。
如果这些信息出现在图片中，请统一写为「已隐藏」。
如果字段看不清，请写「无法确认」。
不要诊断疾病，不要给治疗方案，只输出可用于后续报告解读的结构化内容。
```

转给 `report_agent` 的消息示例：

```text
用户上传了一张检验报告图片，个人身份信息已隐藏。视觉模型识别结果：
- 报告类型：血常规
- 报告日期：2026-06-01
- 白细胞：11.2 x10^9/L，参考范围 3.5-9.5，偏高
- 血红蛋白：无法确认

请基于以上内容进行报告解读。
```

### 药盒图片

```text
请识别这张药品包装图片中的药品信息。
提取药品名称、通用名、规格、生产厂家、批准文号、有效期、用法用量、是否处方药。
如果字段看不清，请写「无法确认」。
不要编造说明书内容，不要给超出图片和药品知识的结论。
```

转给 `pharmacy_agent` 的消息示例：

```text
用户上传了一张药盒图片。视觉模型识别结果：
- 药品名称：布洛芬缓释胶囊
- 规格：0.3g
- 生产厂家：无法确认
- 是否处方药：非处方药

请说明这个药的用途、用法用量、禁忌、注意事项，以及是否适合当前用户。
```

## 前端设计

复用当前 `ScannerOverlay`，将“模拟扫描完成”改为真实图片上传：

1. 用户点击扫描按钮后，打开拍照/文件选择。
2. 本地生成 `previewUrl`。
3. 如果 `scanType === '报告'`，先插入一张模糊报告预览卡。
4. 调用 `/api/vision-chat`，消费 SSE。
5. 根据扫描类型进入对应模式：
   - `报告` -> `report`
   - `药盒` / `追溯码` -> `pharmacy`

建议新增组件：

```text
frontend/src/components/common/SensitiveImagePreview.tsx
```

交互：

- 默认 `blur(16px)`。
- 半透明遮罩文案：`报告可能包含个人信息，按住查看`。
- 按住时临时清晰显示，松开恢复模糊。
- 报告列表和聊天缩略图始终默认模糊。

## 隐私与安全要求

报告图片属于敏感医疗材料，第一版按以下约束实现：

- 后端不落库保存原图。
- 前端只在当前会话内保留 `objectURL` 预览。
- 后端日志不得打印图片 base64、模型原始返回、完整报告文本。
- 视觉模型 Prompt 必须禁止输出个人身份信息。
- 返回给 Agent 的内容必须声明“个人身份信息已隐藏”。
- 上传文件必须校验 MIME、大小，并拒绝非图片文件。
- 外部模型返回内容视为不可信输入，只能作为用户提供的材料进入 Agent，不直接拼接为系统提示词。

## 第一版范围

包含：

- `/api/vision-chat`
- `backend/agents/vision.py`
- 可配置的 OpenAI-compatible 多模态图片识别
- 报告图片模糊预览
- 图片识别结果进入 `report_agent` / `pharmacy_agent`
- 复用现有 SSE、文本回答和卡片渲染

暂不包含：

- 报告永久保存
- 自动打码后的图片存储
- 药品追溯真伪接口
- 识别结果人工编辑页
- 多张图片合并识别

## 后续扩展

如果第一版体验稳定，再逐步增加：

- `report_vision_result` 和 `drug_identification` 专用卡片。
- 报告夹保存脱敏结构化结果。
- 低置信度字段高亮并允许用户修正。
- 药品追溯码接入真实监管或供应链接口。
- 与用户用药提醒、医保购药、附近药店联动。
