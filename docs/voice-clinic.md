# 实时语音问诊设计方案

> 状态：已实现。后端网关、子图改动、前端通话界面和火山引擎 ASR / TTS 适配器均已完成，有脱网单测，并用合成语音做过真实服务的端到端通话（`backend/test_voice_live.py`）。真机验证（M0：麦克风、浏览器回声消除、iOS / Android）未做。“延迟预算”一节是设计时的估算，实测见文末。
>
> 依据：voice-agent 调研项目的 `docs/design/voice-agent-two-architectures.md`（下称 **2A**）和 `docs/knowledge-map.md`（下称 **KM**）。本模块是 2A 定义的 **B 类（有界面移动端、通话式）** 的一个实例，引用写作"2A §3.4""KM 2.5"。

## 目标与范围

在 AI 诊室里增加"通话式"预问诊：用户点一下进入通话，开口说症状，助手用语音追问，屏幕同步显示转写、症状要点和分诊卡片，挂断后得到一张问诊小结。

**MVP 包含**（原一期 + 二期）：

- 通话界面、实时字幕、开放麦连续对话
- 语音打断
- 关键信息复述确认（屏幕可改）
- 每句话都过急症规则闸门，命中后全屏接管
- 问诊小结卡，通话记录写回聊天
- 长辈模式适配、噪声和弱网下的降级

**MVP 不包含**：方言识别、其他专科（医保 / 用药 / 报告）的语音回答、全局输入框的语音听写、端到端语音模型、自托管 ASR / TTS。

## 设计原则

1. **语音是预问诊子图的一层 I/O，不是新的 agent。** 医疗逻辑仍在 `agents/clinic.py`：规则闸门、结构化抽取、充分性检查、`interrupt()` 追问全部复用。语音网关只负责听、判停、决定念什么、播出去。
2. **只走级联，文本先于语音。** 预问诊的每个回合都涉及症状事实和就医建议，属于 2A §3.2 的高风险回合，出声前必须有完整文本可检查。MVP 不接 S2S。
3. **屏幕承载信息，语音承载节奏**（2A §3.4-1）。分诊正文、注意事项、卡片只上屏；语音只念追问、确认和一句结论。
4. **上下文等于屏幕上显示过的内容。** 所有进入对话历史的文本都完整上屏，语音是它的子集。因此打断不需要截断历史（2A §1 原则 2 在有屏幕时由屏幕满足），只在 trace 里记被打断。
5. **出口由规则触发，不由模型触发**（2A §3.4-6）。急症、挂断、"再说一遍"都在进图之前用规则短路。
6. **每个关键事实可见、可改、可确认**（2A §3.4-3）。ASR 会错，症状要点必须在屏幕上看得到、点得改。

## 用户流程

```text
诊室页点"语音问诊"（长辈模式首页有直达大按钮）
  -> 首次使用：授权说明（音频会发给语音服务商，不保存录音）+ 麦克风权限
  -> 进入通话界面，助手先开口："您好，请说说哪里不舒服"
  -> 用户说症状            屏幕：实时字幕 -> 症状要点面板逐项点亮
  -> 助手语音追问（一次一个问题，最多 3 次）
  -> 助手复述确认："我确认一下：头疼，三天了，比较严重，对吗？"
       屏幕同时给 [对，继续] [我要改]，也可以直接点要点修改
  -> 助手："我整理一下" -> 屏幕流式出分诊正文和卡片
       语音只念一句结论 + "详细建议在屏幕上" + 短免责
  -> 用户可继续追问，或挂断
  -> 挂断：生成问诊小结卡，整段对话写回聊天记录，可用文字继续
```

任何时刻命中急症红旗：停止当前播报，念固定安全话术（不可打断），屏幕全屏显示"拨打 120"。

## 通话界面

| 区域 | 内容 |
| --- | --- |
| 顶部 | 咨询人、通话时长、网络状态 |
| 中部 | 状态动效，四态一眼可辨：聆听 / 思考 / 说话 / 异常。思考态显示现有 `node_start` 文案（"正在整理症状要点…"） |
| 症状要点面板 | `SymptomFacts` 七个字段；已填的点亮，缺的置灰；点击可改 |
| 字幕区 | 用户和助手的话都上屏；用户侧先显示 partial，定稿后替换 |
| 底部 | 静音、**说完了**、转文字输入、挂断 |

"说完了"按钮是判停的手动兜底：点它等于立即判停。老人停顿长、环境嘈杂时比任何模型都可靠，长辈模式下放大常驻。

## 架构

```text
┌──────────────────────────────────────────────────────────────┐
│ 前端  screens/Clinic/VoiceCallScreen                          │
│  getUserMedia(AEC/NS/AGC) → AudioWorklet → PCM16 16k ──┐      │
│  播放器(浅缓冲) ← 分句音频      播放回执 ──────────────┤      │
│  字幕 · 症状要点面板 · 卡片 · 按钮(说完了/确认/挂断)   │      │
└────────────────────────────────────────────────────────┼──────┘
                       WebSocket  /api/voice             │
┌────────────────────────────────────────────────────────┼──────┐
│ backend/voice/  语音网关（每通话一个协程）              │      │
│  protocol   帧定义：turn_id / sentence_id / 回执       │      │
│  turns      回合状态机 + 判停 + 看门狗                  │      │
│  shortcuts  进图前规则短路：急症 / 挂断 / 重复         │      │
│  render     事件 → 该念什么（speak_mode）+ 出声前检查  │      │
│  arbiter    代际 + 单一发言者 + 可否打断               │      │
│  asr / tts  适配器（能力声明 + I/O）+ 提示语缓存       │      │
└──────────────┬─────────────────────────────────────────┴──────┘
               │ 同一个 thread_id，HumanMessage / Command(resume)
┌──────────────┴───────────────────────────────────────────────┐
│ master_app（不变） → clinic 子图（小改，见下）                 │
└──────────────────────────────────────────────────────────────┘
```

网关与图之间只有文本。网关对图来说就是另一个 `/api/chat` 调用方：`chat_mode=clinic`、同一个 `thread_id`、挂起时用 `Command(resume=…)`。

### 为什么是 WebSocket 而不是 WebRTC

2A §5 给 B 类的建议是 WebRTC，前提是两端都是 libwebrtc（KM 2.1）。本项目是浏览器 Web 应用，服务端要用 WebRTC 只有 aiortc（无 NACK、无 PLC）或引入 LiveKit 一套基础设施。MVP 选 WebSocket：

- AEC、降噪、AGC 由浏览器在采集端做（`getUserMedia` 约束），这是 AEC 唯一能做的位置（2A §1 原则 7）。
- 按 KM 2.1 补齐 WebSocket 缺的东西：`turn_id`、分句 `sentence_id`、播放回执、服务端按实时限速下发、`tts.stop` 之后零音频。
- 传输藏在 `protocol` 后面，以后换 WebRTC 不动回合和仲裁。

**这是 MVP 最大的技术风险**：浏览器 AEC 对 WebAudio 播放的回声是否消得干净，iOS Safari 和 Android Chrome 表现可能不同，必须真机验证（见"里程碑 M0"）。消不干净时退到半双工：助手说话时麦克风不送判停，打断靠点屏幕。

## 回合模型与判停

回合状态：`listening → committed → thinking → speaking → listening`，每个回合一个 `turn_id`，必须有终态（`done / interrupted / error / superseded`）。

边界来源统一成事件（2A §2.2）：`turn.end{source: vad | button | text | ui}`。语音判停、点"说完了"、打字、点确认按钮是等价输入，走同一个状态机。

**判停** = 流式 ASR 的静音检测 + 自适应等待，放在服务端：

| 参数 | 普通 | 长辈模式 |
| --- | --- | --- |
| 最短等待（静音后） | 0.6 s | 1.0 s |
| 判"没说完"时的最长等待 | 2.5 s | 3.0 s |
| "没说完"的信号（MVP） | partial 以"然后 / 还有 / 就是 / 那个"等结尾，或不足 3 字 | 同左 |

数值是起点，要在样本上调。语义判停模型（smart-turn，KM 2.4）留接口，不进 MVP。

**判停判早了怎么办**（老人停一下又接着说）：回合一旦提交，图的运行不取消。思考期间用户又说的话缓冲成下一回合的输入；当前运行如果以追问结束，这句追问只上屏、不念，直接用缓冲的话 resume。`extract_symptoms` 每次都读完整对话，信息不会丢。这样不需要取消或回滚 LangGraph 的运行。

**看门狗**：

- 聆听 8 秒无人声 → 提示语"您还在吗"；再 20 秒 → 礼貌结束并出小结
- 思考期间不说承接语（"好的""嗯，我记下了"在实测中显得机械，已去掉），只靠屏幕的思考状态；连续 8 秒没有任何可念的内容时（实际只发生在结论回合）念"我还在整理建议，请稍等"，之后每 8 秒重复
- 图连续 20 秒没有任何事件（无进展），或总时长超过 120 秒 → 取消这次运行，回合终态 `error`。取消时不丢访谈：子图本回合已产生的问答（追问、回答、复述）写回父图历史，挂起的步骤标记为结束（`main._abandon_pending_run`），下一句话是一个正常的新回合，基于完整对话继续。如果这次运行期间用户又说了话（已上屏的 `stt.final`），这些话直接作为下一回合送进图；没有的话才念"抱歉，我这边有点慢，您再说一遍好吗"。运行出错时同样处理。
- 运行的生命周期（启动、无进展看门狗、取消、缓冲输入、完成、断线后的收尾）集中在 `voice/runs.py` 的 `RunManager`。

## 每种回合念什么

`render` 把图的事件翻译成"上屏什么、念什么"。所有要念的文本在进 TTS 前都是完整的短句，所以 MVP 用句级 TTS 调用，不需要把 LLM token 流接进 TTS。

| 回合 | 上屏 | 念 | 可打断 |
| --- | --- | --- | --- |
| 开场 | 欢迎语 | 预合成提示语 | 是 |
| 追问（`interrupt`，kind=followup） | 问题气泡，要点面板更新 | 问题原文（子图已限制 ≤ 40 字、单个问题） | 是 |
| 复述确认（kind=confirm） | 要点面板高亮 + 两个按钮 | 模板拼出的复述句，不经 LLM | 是 |
| 分诊结论（`conclude`） | 正文流式 + `clinic_recommendation` 卡片 | 正文第一行是模型按要求写的一句话结论（≤ 40 字，科室 + 紧急程度），切到首个句尾就过检查、送 TTS；卡片的 `summary` 复用这一句。首句不可用时退回念结构化 `summary` | 是 |
| 急症（CRITICAL） | 全屏接管 | 固定安全话术，预合成 | **否** |
| 转接到其他专科 | 目标专科的文本和卡片 | 一句"这个问题我在屏幕上回答您" | 是 |
| 等待 | 状态文案 | 承接语 / 提示语，不进对话历史 | — |

结论回合原本念结构化的 `summary`（和卡片同源），实测要等正文和摘要都生成完，开口在确认后 14–28 秒。现在改为"首句先播"：语音模式的结论提示词要求第一行就是一句话结论，网关切到首个句尾即念，正文继续流到屏幕，卡片随后由摘要生成并复用这一句，耳朵和眼睛仍然一致。

**出声前检查**（规则，同步）：去掉 markdown 和 emoji；数字、单位、"120"按读法规范化；不得出现"您得了 / 确诊"这类绝对诊断措辞；结论句必须带免责短句。不通过就只上屏，语音改念"建议已经显示在屏幕上"。

**提示语**（开场、承接、没听清、还在吗、安全话术、结束语）：启动时用同一音色预合成并缓存，不进模型上下文（2A §1 原则 9）。服务商不可用时至少这些还能出声。

## 打断

- 触发：助手说话期间，人声持续 ≥ 300 ms **且** ASR partial ≥ 2 字且不是附和语（嗯 / 哦 / 好 / 对）。只看 VAD 会被咳嗽和残余回声误触发。
- 动作：代际 +1 → 服务端停发并下发 `tts.stop{turn_id}` → 前端清播放缓冲，回 `playback.interrupted{sentence_id, played_ms}` → 进入聆听。
- 旧输出靠代际过滤丢弃，不靠清队列（2A §1 原则 5）：TTS 迟到的音频帧带旧代际，直接丢。
- 每句开播后前 500 ms 为保护窗，不接受打断。
- 急症安全话术不可打断。
- 追问被打断：用户的话就是回答，直接 resume。
- 点屏幕任意按钮也算打断。

## 关键信息复述确认

在子图的 `check_sufficiency`（信息充分）和 `conclude` 之间加 `confirm_facts` 节点，仅语音通道启用：

1. 用模板把 `collected` 拼成一句复述，`interrupt({"kind": "confirm", "question": …, "facts": …})`。
2. 回答是肯定语（对 / 是的 / 没错 / 嗯，整句锚定匹配，写法同 `is_exit_request`）或点了 [对，继续] → 进 `conclude`。
3. 其他回答视为更正 → 回到 `extract_symptoms` 重新抽取，再确认一次。最多确认 2 次，之后直接 `conclude`。
4. 用户在面板上直接改字段 → 前端发 `ui.action{edit_fact}`，网关把它当作一次输入合并进 `collected`。

`EXTRACT_SYSTEM_PROMPT` 需要加一条："用户后来更正的内容以更正为准"。

ASR 整句置信度低或结果为空时不进图，分三级处理：第一次"不好意思没听清，您再说一遍"；第二次建议点"说完了"按钮或打字；第三次切到手动判停：本次通话余下部分关闭自动判停，只在用户点“说完了”时提交回合。

## 急症处理

**现状有一个缺口**：`emergency_gate` 只在子图入口运行，`await_answer` 恢复后直接进 `extract_symptoms`。用户在回答追问时说出"胸口剧痛、喘不上气"不会触发规则闸门。文字通道同样受影响。

修正：把边 `await_answer → extract_symptoms` 改为 `await_answer → emergency_gate`，闸门读的就是最新一条用户消息，无需其他改动。语音网关另外在进图前对每个定稿句跑一次同样的规则（`EmergencyTriageSkill`，纯规则，毫秒级），这样能在图返回之前就打断播报。

命中 CRITICAL 后：

1. 代际 +1，停止一切播报。
2. 念预合成的固定安全话术，不可打断。
3. 屏幕全屏接管：红色警示、识别到的危险信号、`tel:120` 拨号按钮、注意事项。**不自动拨号**，由用户点。
4. 通话进入 `emergency` 态，不再追问。只有点"我没事，继续问诊"才能退出（防误报，且必须是点击，不接受语音）。

`conclude` 得出 `urgency=emergency` 时同样触发接管。

## 会话、重连与结束

- 一次通话一个 `thread_id`（2A §3.2"一任务一会话"），与文字聊天共用。从已有的预问诊文字对话进入通话时沿用原 `thread_id`。
- 断线重连：前端带 `thread_id` 重连，checkpointer 里有完整状态和挂起的 `interrupt`，网关重新念一遍挂起的问题即可。checkpointer 在这里就是 2A 说的"会话重建器"。切后台超过 30 秒视为挂断。
- 断线时正在跑的图**不取消**：它在后台跑完，结果（追问 / 复述 / 结论）落进 checkpoint；后台运行以本次运行剩余的 120 秒总时长为上限，超时才取消并按上面的方式收尾，不会泄漏任务。同一 `thread_id` 的重连会先等这次后台运行结束（期间状态为"思考"），再读 checkpoint，避免两个运行同时写一个会话。只有用户主动结束（挂断、退出词、长时间无声）才取消正在跑的图。
- 语音里说出退出词（`is_exit_request`）→ 网关直接结束通话，不把它送进图。
- "再说一遍 / 没听清" → 网关重播上一句，不进图。

**结束时的产出**（2A §3.4-5）：

- `clinic_summary` 卡片：咨询人、起止时间与时长、主诉与症状要点、建议科室、紧急程度、注意事项、识别到的危险信号、免责声明。全部取自 `collected` 和 `recommendation`，不另调 LLM（`voice/gateway.py` 的 `build_clinic_summary`）。没到结论就挂断的，`status` 为 `incomplete`，只列已收集的要点。
- 字幕和卡片写入 `GlobalContext.messages`，`threadId` 保留，用户可以用文字接着问。

## 客户端协议（`/api/voice`）

帧格式的权威定义是 `contracts/voice-frames.json`（每种帧的字段、类型、可选字段和取值范围）。后端测试按它检查网关发出的每一帧，前端的模拟服务器按它检查浏览器客户端发来的每一帧和自己发出的每一帧，任何一方单独改协议都会有测试失败。下面的表格是说明，与契约文件不一致时以契约文件为准。

控制帧为 JSON，音频为二进制帧（PCM16 / 16 kHz / 20 ms，帧头带序号和采样计数）。

上行：

| 帧 | 说明 |
| --- | --- |
| `hello{thread_id?, user_info, caps}` | `caps` 声明 AEC 是否可用、采样率、是否支持回执；服务端据此决定开放麦还是半双工 |
| 音频帧 | 静音键按下时不发 |
| `turn.end{source}` | 点"说完了" |
| `input.text{text}` | 打字输入 |
| `ui.action{kind, …}` | `confirm` / `edit_fact` / `emergency_dismiss` |
| `playback.started / ended / interrupted{turn_id, sentence_id, played_ms}` | 播放回执 |
| `bye` | 挂断 |

下行：

| 帧 | 说明 |
| --- | --- |
| `session{thread_id}` | 首帧，与 SSE 一致 |
| `state{listening / thinking / speaking / emergency}` | 驱动状态动效 |
| `stt.partial / stt.final{turn_id, text}` | 字幕 |
| `text` `card` `node_start` `node_end` `tool_start` `tool_end` `interrupt` | **与现有 SSE 事件同形**，前端复用 `ChatServiceOptions` 的处理；`interrupt` 多带 `kind` |
| `facts{collected, missing, version}` | 症状要点面板 |
| `tts.sentence{turn_id, sentence_id, text, interruptible}` + 音频帧 | 按实时限速下发，超前 200–500 ms |
| `tts.stop{turn_id}` | 之后该回合零音频 |
| `error{class, content, action?}` | `class` 见下；`action: "push_to_talk"` 表示已切到手动判停 |
| `summary` | 挂断后的小结卡 |

错误分四类（2A §1 原则 8）：`fatal`（鉴权、配额，重试无用，直接转文字）/ `transient`（ASR 或 TTS 连接断，每回合最多重连 3 次）/ `degraded`（TTS 不可用但还能上屏，继续通话并提示看屏幕）/ `benign`（取消竞态，不提示）。

对现有代码的改动：

- `main.py`：把 `_stream_agent_events` 拆成"产出事件字典的生成器"和"SSE 包装"两层，语音网关消费前者。挂载 `/api/voice`。CORS 对 WebSocket 不生效，需在握手时校验 `Origin`。
- `agents/clinic.py`：`await_answer → emergency_gate` 的边；`confirm_facts` 节点；`ClinicState` 加 `channel`；抽取提示词加更正规则；`interrupt` 的值从字符串改为带 `kind` 的字典（`main._interrupt_question` 已支持字典）。
- `agents/state.py`：`MainAgentState` 加 `channel: "text" | "voice"`，默认 `text`，文字通道行为不变。
- **通道是每次请求的事实，不从 checkpoint 继承**：调用方在每次运行的 config 里带 `configurable.channel`（`/api/chat`、`/api/vision-chat` 为 `text`，语音网关为 `voice`），包括 `Command(resume=…)` 恢复；子图节点优先读 config，state 里的 `channel` 只是没传时的兜底。因此语音通话停在复述确认上挂断后，用户在文字聊天里回一句，按文字处理：回答直接作为确认答复，肯定就出结论，更正就重新抽取后直接出结论，不再走语音复述，也不带语音首句指令；反过来，文字里开始的问诊在语音通话里继续，会正常走语音复述。
- `.env.example`：`ASR_PROVIDER` / `TTS_PROVIDER` 及对应密钥，解析方式仿 `agents/llm.py`（不联网校验，可单测）。

ASR / TTS 适配器用**能力声明**而不是按服务商名分支（2A §1 原则 4）：ASR 声明是否有 partial、端点事件、热词、置信度；TTS 声明是否支持语速、句级时长。默认服务商建议火山引擎（与默认的 ARK 同一账号体系；KM 2.6、2.9 列了豆包流式 ASR 与火山双流式 TTS），百炼作为第二实现，以验证适配层没有写死。症状和常见药名作为 ASR 热词。

## 长辈模式

- 判停等待更长（见上表），"说完了"按钮放大常驻
- TTS 语速约 0.85 倍，字幕和要点面板用大字号
- 首页提供"语音问诊"直达入口
- 没听清时优先引导按钮，而不是反复要求重说

## 隐私

- 原始音频不落盘、不进日志、不进 trace，只在内存里转发。
- 音频会发给第三方语音服务商，首次使用的授权说明里必须写明。
- ASR 定稿文本进图前过 `redact_sensitive_text`（用户可能念出手机号、证件号）。
- 转写文本属于健康信息，沿用现有规则：不打日志；`TRACE_CONTENT` 关闭时 span 里只有时长、枚举和 id。
- 测试和评测只用合成或脱敏的音频样本。

## 可观测性与评测

每回合 trace（KM 2.12 的子集）：判停等待时长、判停来源、ASR 定稿耗时与置信度、**有声音**（首个提示语或正文）与**有内容**（首句正文）分开计时、`speak_mode`、回合终态、是否被打断、已播放时长 / 已生成时长、重听次数、错误类别、是否降级。

测试沿用仓库的两类划分：

- **确定性单测**（无网络，脚本化的假 ASR / TTS / 模型，仿 `test_fakes.py`）：按事件序列断言（2A §1 原则 11）。必须覆盖：打断后旧代际音频被丢弃；判停过早时的缓冲与跳过追问；追问回答里出现红旗词触发接管；确认—更正—再确认的次数上限；安全话术不可打断；断线重连后重念挂起的问题；结论句未通过出声前检查时只上屏。有竞态的用例重复跑出通过率。
- **需要真实服务的脚本**：首包延迟、判停参数扫描、真机回声测试，手动运行，不进 CI。

`evals/cases.jsonl` 增加语音通道的用例（`channel=voice`）：至少一条正常路径和一条安全边界（追问中途出现急症）。

## 延迟预算（从判停算，估算）

| 段 | 目标 | 手段 |
| --- | --- | --- |
| 判停 | 0.6–1.0 s | 静音 + 自适应等待；"说完了"按钮为 0 |
| 有声音 | ≤ 1.0 s | 状态立即切"思考"（屏幕）；不再用承接语填充 |
| 追问有内容 | 2–3 s | 抽取和追问各一次 LLM 调用，串行 |
| 结论有内容（屏幕） | 2–3 s 起流 | 正文流式上屏 |
| 结论有内容（语音） | 5–8 s | 等结构化摘要 |

追问回合超出 2A §3.3 的 1.5 秒目标，瓶颈是子图里串行的两次 LLM 调用。优化方向是把"抽取 + 生成追问"合并成一次结构化输出，但这会改动文字通道已有的行为，MVP 先测量，不先改。

## 实测记录（合成语音，火山引擎 `bigmodel_async` + `seed-tts-1.0`，模型 `doubao-seed-2-0-lite`，思考已关）

`test_voice_live.py e2e --calls 2`，同一服务进程连打两通（冷 / 热），时间为**首个音频**到达的时刻。

| 段 | 优化前 | 优化后（冷 / 热） |
| --- | --- | --- |
| 说完到回合提交 | 0.2–0.3 s | 0.2–0.3 s |
| TTS 首包 | 0.3–0.5 s | 0.3–0.5 s |
| 追问出声（提交后） | 3.6–4.7 s（帧到达） | 3.0 / 3.0 s |
| 复述确认出声（提交后） | 1.5–2.3 s（帧到达） | 3.5 / 2.9 s |
| 结论正文开始上屏（确认后） | 6.6–18.6 s | 5.0 / 5.6 s |
| 结论语音（确认后） | 14–28 s | **5.7 / 6.1 s** |
| 分诊卡片（确认后） | 13.9–26.6 s | 12.8 / 12.5 s |

做了三件事：RAG 启动时预热且嵌入模型离线加载（原先第一次检索 10.3 s，是 HuggingFace 联网检查超时）；技能工具改为直接字段参数（原先 `symptom_scorer` 的 `params_json` 字符串常被模型传错，校验失败后重试）；结论首句先播；抽取与追问合并为一次结构化调用。模型首 token 实测 1.3–1.7 s，是每个环节的下限。

剩余的时间：复述确认仍需一次抽取调用；结论回合在 ReAct 里先调一次 `symptom_scorer` 再写正文，卡片要等正文写完再做一次摘要（约 2 s）。下一步可做：语音模式下在代码里直接调 `symptom_scorer`、省掉 ReAct 的工具往返；用更小档位的模型做抽取。
